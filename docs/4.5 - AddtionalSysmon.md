# Additional Sysmon Event IDs

## Objective
Learn and practice investigating common Sysmon events by analysing simulated scenarios. Focused on how to interpret Sysmon Event IDs 3, 11, and 13 by understanding the fields and what they mean, identifying normal and suspicious behaviour, and correlating multiple events.

## Topics Covered

### Event ID 3 - Network Connection 
Records when a process initiates a network connection

Important fields:
- Image: The executable that created the network connection
- User: The account that initiated the connection
- Destination IP: The remote IP address the process connected to
- Destination Port: The remote port used for the connection
- Protocol: The network protocol used (TCP/UDP)

Investigation Example: Used PowerShell to connect to a website

Sysmon Event Analysis:
- Image: C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
- User: vboxuser
- Destination Port: 443
- Protocol: TCP

This event showed that PowerShell created an HTTPS connection. This action was intentional by me therefore expected behaviour.
To determine if a network connection is malicious, investigate the destination IP address, the process, the command executed, and any other activities that may have occurred.

### Event ID 11 - File Creation
Records when a process creates a file

Important fields:
- Image: The executable that created the file
- TargetFilename: The full path and filename that was created
- User: The account that created the file
- Process ID: The process responsible for creating the file

Investigation Example: Used PowerShell to create a PowerShell script named test.ps1 on the Desktop

Sysmon Event Analysis:
- Image: C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
- TargetFilename: C:\Users\vboxuser\Desktop\test.ps1
- User: vboxuser

This event showed that PowerShell created the file test.ps1 on the Desktop. I originally tried creating a text file, but Sysmon did not record this event because it is not considered a file type that the configuration is set to monitor. This activity is expected since I created the file. 
However, it would be suspicious if PowerShell created an unknown executable and placed it in an unusual location, along with other factors such as if additional processes were created or any Registry changes occurred.

### Event ID 13 - Registry Value Set
Records when a Registry value is modified

Important fields:
- Image: The executable that modified the Registry
- TargetObject: The Registry key or value that was modified
- Details: The value written to the Registry
- User: The account that modified the Registry

Investigation Example: Used PowerShell to create a Registry Run key entry pointing to Notepad.

Sysmon Event Analysis:
- Image: C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
- TargetObject: HKCU\Software\Microsoft\Windows\CurrentVersion\Run\exampleTest
- Details: C:\Windows\System32\notepad.exe
- User: vboxuser

This event showed that PowerShell modified the Windows Registry by creating a Run key entry that opens Notepad, which is expected since I intentionally created the Registry value.
However, activity can be suspicious if an unknown executable adds itself to the Run key, unexpected Registry modifications, or a malicious process making the Registry changes.

### Reflection
Learning these additional common Sysmon Event IDs showed me how to investigate different types of endpoint activity, including network connections, file creation, and Registry modifications. Since malicious activity is usually a chain of events, understanding how each Event ID operates is useful for seeing the full picture and identifying suspicious behaviour.
